**PQC (Post-Quantum Cryptography)**

 ชุดอัลกอริทึมการเข้ารหัสลับที่ถูกออกแบบมาให้ทนทานต่อการโจมตีจากทั้งคอมพิวเตอร์คลาสสิกและคอมพิวเตอร์ควอนตัม
 
**ความท้าทายในการเปลี่ยนผ่านสู่มาตรฐาน PQC:** วิเคราะห์ความกดดันที่ผู้ผลิตโดรนและสตาร์ทอัพต้องเผชิญ ทั้งในแง่ของกฎระเบียบโลก (เช่น CNSA 2.0) และความคุ้มค่าเชิงธุรกิจในการลงทุนกับเทคโนโลยีที่ยังอยู่ในช่วงเริ่มต้น

-----
**Post-Quantum Cryptography (PQC) Secure Boot** หมายถึงการรักษาความปลอดภัยของกระบวนการบูต (โดยเฉพาะ UEFI Secure Boot และ Root-of-Trust ของเฟิร์มแวร์/ระบบฝังตัว) โดยใช้ขั้นตอนวิธีลายเซ็นดิจิทัลที่ต้านทานควอนตัม แทนที่ (หรือใช้ร่วมกับ) ขั้นตอนวิธีแบบคลาสสิก เช่น RSA-2048 หรือ ECDSA

### ทำไมจึงสำคัญ
Secure Boot ในปัจจุบันพึ่งพาการเข้ารหัสด้วยกุญแจสาธารณะ (ส่วนใหญ่เป็น RSA และ ECC) ซึ่งคอมพิวเตอร์ควอนตัมขนาดใหญ่ที่ใช้ Shor’s algorithm สามารถทำลายได้ เฟิร์มแวร์และอิมเมจบูตมีอายุการใช้งานยาวนานมาก จึงต้องเริ่มย้ายไปใช้เทคโนโลยีใหม่ตั้งแต่เนิ่น ๆ  
CNSA 2.0 ของ NSA กำหนดให้การลงนามซอฟต์แวร์/เฟิร์มแวร์ใช้ขั้นตอนวิธีที่ปลอดภัยจากควอนตัมเป็นค่าเริ่มต้นภายในประมาณปี 2025 และเป็นทางเลือกเดียวภายในปี 2030 หน่วยงานระดับชาติอื่น ๆ ก็มีแนวทางคล้ายกัน

### ขั้นตอนวิธี PQC ที่เกี่ยวข้องกับ Secure Boot
ตัวเลือกที่ NIST มาตรฐานหรือแนะนำ และมักถูกใช้หรือประเมินสำหรับบูต:

| ขั้นตอนวิธี              | มาตรฐาน / สเปก          | ประเภท                  | หมายเหตุสำหรับ Secure Boot |
|------------------------|--------------------------|-----------------------|-----------------------|
| **ML-DSA** (Dilithium) | FIPS 204                | แบบแลตทิซ (ไม่มีสถานะ) | ตัวเลือกหลักสำหรับงานทั่วไป สมดุลดีระหว่างขนาดและประสิทธิภาพ |
| **SLH-DSA** (SPHINCS+) | FIPS 205                | แบบแฮช (ไม่มีสถานะ)   | ความปลอดภัยสูงมาก ลายเซ็นใหญ่ ได้รับความนิยมในฮาร์ดแวร์เปิดบางตัว (เช่น OpenTitan) |
| **LMS / HSS**          | RFC 8554 / NIST SP 800-208 | แบบแฮช (มีสถานะ) | ความเร็วในการตรวจสอบดีเยี่ยม และลายเซ็นเล็ก การจัดการสถานะเป็นความท้าทายหลัก |
| **XMSS**               | RFC 8391                | แบบแฮช (มีสถานะ) | คล้ายกับ LMS |

แนวทางแบบไฮบริด (ลายเซ็นคลาสสิก + PQC) ถูกแนะนำอย่างกว้างขวางในช่วงเปลี่ยนผ่าน เพื่อความคล่องตัวทางคริปโตและความต่อเนื่อง

### ความคืบหน้าในอุตสาหกรรม
- **UEFI Forum**: กำลังปรับปรุงสเปกเพื่อรองรับความคล่องตัวทางคริปโตใน Secure Boot (รองรับหลายลายเซ็น ตัวบ่งชี้ขั้นตอนวิธี การเปลี่ยนแปลงการจัดการ db/dbx/PK/KEK และ EFI Crypto Indicator Table) เป้าหมายคือทำให้โครงสร้างพื้นฐานพร้อมสำหรับ PQC โดยไม่บังคับขั้นตอนวิธีเฉพาะ
- **โซลูชันฮาร์ดแวร์**:
  - Microchip Trust Shield TS1800 / TS50x: เร่งด้วยฮาร์ดแวร์สำหรับ ML-DSA, LMS, ML-KEM ใน Platform Root of Trust และตัวควบคุม Secure Boot
  - PQSecure Technologies: PQSecure-Boot (HW IP + ไลบรารีซอฟต์แวร์) รองรับ ML-DSA, LMS, SLH-DSA
  - อื่น ๆ: SEALSQ, PQShield, OpenTitan (SPHINCS+/SLH-DSA ใน mask ROM), และ IP core สำหรับ FPGA/ASIC ต่าง ๆ
- **การนำไปใช้จริง**: HP เปิดตัว Secure Boot แบบไฮบริด RSA + LMS ที่ปลอดภัยจากควอนตัมตั้งแต่ปี 2024 OpenTitan รองรับ post-quantum secure boot ด้วย SPHINCS+ ตั้งแต่ตัวอย่างซิลิคอนรุ่นแรก

### ข้อควรพิจารณาในทางปฏิบัติ
- **ประสิทธิภาพการตรวจสอบ** สำคัญมาก (ต้องเร็วบน boot ROM หรือเฟิร์มแวร์ระยะแรกที่มีข้อจำกัด) ขั้นตอนวิธีแบบแฮชมักทำได้ดีในจุดนี้
- **ขนาดลายเซ็นและกุญแจ** ใหญ่กว่า RSA/ECDSA → ส่งผลต่อการจัดเก็บในแฟลช ฐานข้อมูลใบรับรอง และเวลาในการถ่ายโอน
- **ขั้นตอนวิธีที่มีสถานะ** (LMS/XMSS) ต้องจัดการสถานะกุญแจอย่างระมัดระวังเพื่อป้องกันการใช้ซ้ำ การสูญเสียสถานะอาจทำให้การอัปเดตใช้ไม่ได้
- **ความคล่องตัวทางคริปโต** จำเป็น: ระบบควรรองรับหลายขั้นตอนวิธีและลายเซ็นไฮบริด เพื่อให้เปลี่ยนขั้นตอนวิธีได้ในภายหลังโดยไม่ต้องออกแบบฮาร์ดแวร์ใหม่
- **Root of Trust** ต้องปลอดภัยจากควอนตัมตั้งแต่เปิดเครื่องครั้งแรก (การตรวจสอบที่บังคับด้วยฮาร์ดแวร์ดีกว่าการใช้ซอฟต์แวร์ล้วน)
- อุปกรณ์เดิมบางตัวอาจได้รับความคุ้มครองบางส่วนผ่านการออกแบบที่ชาญฉลาด (เช่น ใช้เฉพาะสมมาตร/แฮช หรือตัวควบคุม RoT ภายนอก) แต่การป้องกันเต็มรูปแบบมักต้องใช้ซิลิคอนใหม่หรืออัปเดตเฟิร์มแวร์ในกรณีที่ทำได้

### สรุป
PQC Secure Boot เป็นหัวข้อที่มีความสำคัญสูงและมีการพัฒนาอย่างต่อเนื่อง เส้นทางที่แนะนำคือใช้ลายเซ็นไฮบริดในปัจจุบัน แล้วค่อย ๆ ย้ายไปใช้ PQC ล้วน (หลัก ๆ คือ ML-DSA หรือแบบแฮช) เมื่อมาตรฐานเติบโตเต็มที่และการรองรับฮาร์ดแวร์แพร่หลายมากขึ้น UEFI ผู้ผลิตซิลิคอนรายใหญ่ และแนวทางจากหน่วยงานรัฐบาล ล้วนสอดคล้องกันในการทำให้การเปลี่ยนผ่านนี้เป็นไปได้จริงทั้งในคอมพิวเตอร์และระบบฝังตัว/IoT
